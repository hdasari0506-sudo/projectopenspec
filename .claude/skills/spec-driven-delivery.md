# Spec-Driven Delivery

Use this skill for work that introduces or changes product behavior, APIs, workflows, or architecture.

## Process

1. Understand the goal and constraints.
2. Write or update a spec in `specs/`.
3. Create or revise the implementation plan in `plans/`.
4. Identify required validation gates.
5. Implement in small, reviewable steps.
6. Run the smallest relevant tests or checks.
7. Confirm the result meets the acceptance criteria.

## Deliverables

- A clear user-facing problem statement.
- Functional requirements and edge cases.
- Acceptance criteria and validation steps.
- A phased implementation path when useful.

## Guardrails

- Do not implement without a spec when the work is non-trivial.
- Do not hide uncertainty; express open questions.
- Keep scope bounded.
- Favor verification over assumptions.
